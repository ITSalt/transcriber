## User story

## API endpoints / worker contract

| Method | Path | Description |
|--------|------|-------------|
| POST | `/api/uploads/init` | Validate metadata, create the S3 multipart upload, return `s3_key`, `s3_upload_id`, `part_size` and one presigned URL per part |
| PUT | *(presigned S3 URL, per part)* | **Browser → object storage directly.** Does not traverse the API. |
| POST | `/api/uploads/complete` | Complete the multipart upload, ffprobe the object, persist rows, enqueue the job |
| POST | `/api/uploads/abort` | Abort the multipart upload and release already-uploaded parts |

> **Transport correction.** The former TUS endpoints (`POST /api/uploads`,
> `PATCH /api/uploads/:uploadId`, `POST /api/uploads/:uploadId/finalize`) never
> shipped. `@tus/server` and `tus-js-client` are in no `package.json`, and
> `api/src/plugins/tus.ts` does not exist. ADR-012 (direct S3 presigned
> multipart) supersedes ADR-005 (TUS) in the graph. Contract:
> `.tl/external-contracts/s3-multipart-presigned.md`.

See `api-contract.md` for full request/response schemas and error codes.

## System steps (main flow)

1. On `POST /api/uploads/init`: validate `size_bytes <= 1 GiB` (RQ-008) and `mime_type` in {video/mp4, video/x-matroska, video/quicktime, video/webm} (RQ-009). Reject before any storage object is created, with 4xx + error code.
2. Create the S3 multipart upload under `pending/<uuid>.<ext>`, presign every part, and return them with `part_size`. The browser PUTs parts directly to object storage — bytes never traverse the API.
3. On `POST /api/uploads/complete`: complete the multipart upload, then `probeContainer` via ffprobe against the assembled object (RQ-010). On failure → abort/delete the object + return 422.
4. In a single DB transaction: insert Meeting(status=UPLOADING, language=hint|null, title=hint|filename-no-ext per RQ-013), insert Recording(filename, size_bytes, mime_type, storage_uri), enqueue TranscriptionJob(status=PENDING, meeting_id), transition Meeting.status -> TRANSCRIBING (RQ-011). Recording is reached via meeting_id at worker pickup; TranscriptionJob has no recording_id column.
5. Return {meeting_id} so client can redirect to UC-002.

## Enumerations

#### `MeetingStatus`
- `CREATED` — Meeting row exists; upload not yet started
- `UPLOADING` — File upload in progress
- `UPLOADED` — Upload finalized; TranscriptionJob not yet enqueued
- `TRANSCRIBING` — Transcription queued or running
- `TRANSCRIBED` — Transcript persisted; protocol not yet started or running
- `GENERATING_PROTOCOL` — Protocol-gen job queued or running
- `PROTOCOL_READY` — Protocol persisted; no manual edits yet
- `EDITED` — Protocol manually edited at least once
- `ERROR` — Non-recoverable pipeline error (terminal, BRQ-009)

#### `MeetingLanguage`
- `RU` — Russian
- `EN` — English

#### `VideoMimeType`
- `video/mp4` — MP4 container
- `video/x-matroska` — MKV container
- `video/quicktime` — MOV container
