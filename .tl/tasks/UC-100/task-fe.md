## User story

> As an Author, I want to upload a meeting video of up to 1 GiB with an optional
> protocol-language choice, so the system starts transcription.

## Acceptance criteria

- GIVEN a valid MP4/MKV/MOV/WebM file <= 1 GiB (BRQ-001, BRQ-002), WHEN I upload, THEN the system accepts, creates Meeting + Recording + TranscriptionJob, and shows status UPLOADING -> TRANSCRIBING.
- GIVEN a file > 1 GiB or a MIME type outside the accepted set, WHEN I attempt upload, THEN the system rejects before storage with a clear error.
- GIVEN a corrupt file (BRQ-003), WHEN validation fails, THEN the system rejects with a user-facing error.
- I can choose RU or EN as the protocol language; leaving it blank means AUTO — the protocol is generated in **Russian** (BRQ-013) and the ASR auto-detects the spoken language (BRQ-005). Choosing EN is the only way to get an English protocol (RQ-012).
- I may optionally supply a speaker-count hint (1–10) to pin diarization (RQ-037).

## User steps

1. AUTHOR navigates to /upload. *(UC-100-AS01)*
2. AUTHOR selects a video file via the picker and optionally sets the protocol language (RU / EN / blank = AUTO = Russian protocol + ASR auto-detection) and title (defaults to filename). *(UC-100-AS02)*
3. AUTHOR clicks Upload. *(UC-100-AS03)*
4. System validates size / MIME / container integrity; on failure shows an inline error and returns to step 2 with no Meeting, Recording or storage object created. *(UC-100-AS04, AS05)*
5. System creates Meeting (UPLOADING) + Recording in one transaction, then uploads the file to object storage, reporting progress to the client. *(UC-100-AS06, AS07)*
6. On completion, System creates the TranscriptionJob and transitions Meeting.status UPLOADING -> TRANSCRIBING. *(UC-100-AS08)*
7. AUTHOR is redirected to /meetings/:id with a success toast. *(UC-100-AS09)*

> **Transport note.** AS07 reads "streams the file in chunks to EXT-04". The
> shipped mechanism is **S3 presigned multipart**: `POST /api/uploads/init`
> returns per-part presigned URLs, the browser PUTs parts directly to object
> storage (never through the API), then `POST /api/uploads/complete` finalizes.
> Progress is computed client-side from completed parts — there are no TUS
> progress events. See `.tl/external-contracts/s3-multipart-presigned.md`.

## Enumerations (UI display + filtering)

#### `MeetingStatus`
- `UPLOADING` — File upload to object storage is in progress
- `TRANSCRIBING` — Transcription job queued or running (ASR + diarization)
- `TRANSCRIPT_READY` — Transcript persisted; protocol generation not started yet
- `PROTOCOL_GENERATING` — LLM protocol-generation job queued or running
- `PROTOCOL_READY` — Protocol generated and persisted; no manual edits yet
- `EDITED` — Protocol manually edited at least once
- `FAILED` — Non-recoverable pipeline error (terminal, BRQ-009)

> Prisma ships `TRANSCRIBED` and `GENERATING_PROTOCOL` for the two middle states.
> Use the schema values in code; the graph vocabulary is pending reconciliation.

#### `MeetingLanguage`
- `RU` — Russian. Used as the ASR language hint and selects the Russian prompt template.
- `EN` — English. Used as the ASR language hint and selects the English prompt template.
- `AUTO` — Author declared no document language. Protocol is generated in **Russian** (BRQ-013); ASR runs with auto-detection (BRQ-005) and the detected value is recorded on `Transcript.language`. Valid on `Meeting.language` only — **never** a legal value for `Transcript.language`.

#### `VideoMimeType`
- `video/mp4` — MP4 container
- `video/x-matroska` — MKV container
- `video/quicktime` — MOV container
- `video/webm` — WebM container
