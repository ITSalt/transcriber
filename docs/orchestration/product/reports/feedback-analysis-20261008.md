## 5. Выводы и рекомендации

**Что из обратной связи закрывается существующими средствами (нужна только карточка проекта и контекст):** роли/организации участников (c0, 20.05 #4), разделение тёзок (20.05 #1), ошибочные имена из ASR (20.05 #3, TCB #3), единообразие терминов (TCB #3), структура по продуктам и формат задач (c10–c14) — 10 из 18 пунктов. Для этого на проде теперь включены keyterms (D-36) и работает контекст в промпте.

**Что не закрывается контекстом и требует изменений продукта:**
1. **Имена спикеров** (c15, c16, TCB #1) — главная боль пользователя. Правило `speaker_mapping` намеренно консервативно; Haiku 5.5 при нём и даёт больше имён, и ошибается (B TCB). Рекомендация — предложение из TCB #1: шаг «подтвердить спикеров» после транскрибации и до протокола: пользователю показывают по 2–3 цитаты на каждый Speaker N и список участников проекта, он сопоставляет; сопоставление идёт в промпт как факт. Отдельный пакет (api: сохранение карты спикеров; worker: подстановка имён в транскрипт до LLM; web: экран).
2. **Диаризация** (20.05 #2, TCB #1): `speaker_count` не доходит до Deepgram (D-21). Проверить, можно ли передать `diarize_version`/число спикеров через `listen` без SDK-фильтра, либо принять.
3. **Утечка памяти проекта в протокол** (новая находка): факты и участники из памяти/карточки попадают в обсуждение и решения чужой встречи. Ужесточить промпт: память — только для `## Перенесённые задачи` (отдельная секция) и написания имён; явный запрет переносить факты, которых нет в транскрипте; тест на фикстуре двух встреч.
4. **Смысловые споры** (c6) не решаются автоматически — только правкой пользователя; обратная связь по протоколу (FR-005) для этого и нужна.
5. **Метаданные**: `ProtocolGeneration.asr_options` помечены `source: reconstructed` и отражают флаг на момент генерации, а не что получил ASR — писать keyterms/флаг в `transcription_jobs` при распознавании.
6. **Память**: дедуп решений по смыслу и валидация исполнителя по списку участников (не выдумывать имена).

**Инфраструктура (сделано сегодня):** kie.ai нестабилен (500 на длинных генерациях), переход на OpenRouter через прокси владельца (WP-WORKER-03/04/05), reasoning отключён по умолчанию, keyterms включены. Стоимость протокола длинной встречи на Haiku 5.5 — около 0,005 USD, время ~20 с (kie.ai Sonnet: 35–100 с и сбои).

**Условие завершения программы:** п. 3 (встреча с проектом и контекстом: keyterm в запросе Deepgram — лог «ASR keyterms prepared» 47/27/47, XML-секции в промпте — архив в S3, снимок контекста и метаданные генерации — SELECT) и память проекта подтверждены этим прогоном под пользователем «Тест»; R-19 закрыт по этим фактам (D-38).
