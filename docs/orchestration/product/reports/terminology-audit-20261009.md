# Ревизия терминологии: глоссарий, код, UI/UX — 2026-10-09

Запрос владельца 2026-10-09: «задача» в главном меню открывает список встреч; задача — это
поручение одному или нескольким участникам встречи с контекстом и сроком; создаём и загружаем
мы встречу; встреча — по проекту; задачи — по проекту на основе протокола встречи. Провести
ревизию глоссария, аудит кода и UI/UX, составить план устранения неоднозначностей.

Источники: граф спецификации `codex-transcriber-knowledge-neo4j` (bolt 3627, read-only
запросы), `origin/main` 5392bbe (одноразовый клон в scratchpad), workspace программы
`product` (PLAN.md, decisions.md). Ничего не менялось: ни в репозитории, ни в графе.

## 1. Итог

1. Корень двусмысленности — допущение A-2 (2026-10-07) и п. 3 PLAN.md: «задача в UI =
   сущность Meeting». С выходом памяти проекта (FR-006, UC-601…603) в продукте появилась
   настоящая задача (поручение, код T-n), и слово «Задачи» теперь означает две разные вещи
   на соседних экранах: в главном меню — список встреч, на карточке проекта — реестр поручений.
   Владелец 2026-10-09 отменил A-2 (D-40 ниже).
2. Глоссарий графа (28 терминов GLO-001…028, все `status: draft` от 2026-05-17) отстал от
   продукта на три программы: нет терминов Пространство, Проект, Участник проекта, Контекст
   встречи, Снимок контекста, Задача (реестр), Решение (реестр), Событие задачи, Память проекта,
   Версия протокола, Обратная связь, Подтверждение спикеров, Ключевой термин (keyterm). Русские
   синонимы всех 28 терминов в графе испорчены (строка «Встреча» хранится как 14 знаков «?»).
3. Код: модель, API и контракты уже говорят правильно (`Meeting`, `/api/meetings`,
   `/api/projects/:id/tasks`, секция «## Задачи» протокола = поручения). Расхождение живёт
   только в строках интерфейса, тестах и комментариях — исправление дешёвое.
4. Попутно найдены ещё 9 несоответствий UI/UX (раздел 4), из них одно вводит пользователя
   в заблуждение: поле «Количество спикеров» на загрузке обещает улучшить разделение по
   голосам, а в Deepgram оно сознательно не передаётся (D-21).

## 6. Открытые вопросы владельцу

- P-20 — поле «Количество спикеров» на загрузке: (а) убрать; (б) оставить с честной
  подсказкой «используется только как подсказка протоколу». Рекомендация: (а) — значение
  никуда не идёт (D-21), а подтверждение спикеров (UC-505) закрывает потребность.
- P-21 — метка неподтверждённого спикера: (а) «Speaker N» везде (так в Deepgram, промптах и
  экране подтверждения); (б) «Спикер N» везде (транскрипт уже так). Рекомендация: (б) для
  русского интерфейса и протокола, (а) остаётся во внутренних данных (`speaker_map`).
- P-22 — после переименования меню «Задачи» → «Встречи» реестр поручений остаётся доступен
  только с карточки проекта. Нужен ли пункт меню «Задачи» со сводным реестром по всем
  проектам пространства (новая страница, `/api/projects/:id/tasks` по каждому проекту или
  новый сводный маршрут)? Рекомендация: отложить в backlog до анализа обратной связи — сейчас
  задачи живут в контексте проекта, и это соответствует словарю владельца.
