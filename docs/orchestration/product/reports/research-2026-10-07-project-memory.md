# Исследование Q-3: память проекта, задачи и решения как граф (2026-10-07)

Субагент, веб-источники; выводы — утверждения, не проверенные на нашем коде.

## Практика рынка
- Fellow переносит незакрытые action items в следующую встречу серии, статус ставит человек (help.fellow.app/en/articles/4495786).
- Read AI заявляет авто-статусы задач по нескольким встречам, механизм не раскрыт (read.ai/for-you).
- Otter/Fireflies/tl;dv: межвстречевой трекинг не подтверждён. Норма рынка — перенос открытых + подтверждение человеком.
- Извлекать задачи из транскрипта, не из саммари (полнота из саммари ~71%); пайплайн Extract → Verify (цитата сверяется с текстом) → Resolve.
- Entity resolution: blocking (дешёвые кандидаты: лексика/эмбеддинги/исполнитель) → matching (LLM только на коротком списке) (arXiv 2304.12329).

## Защита от выдуманных закрытий
1. Любое изменение статуса — с дословной цитатой и таймкодом; код проверяет, что цитата есть в сегментах Deepgram.
2. «Не упомянута» = NO_CHANGE. Закрытие только по явной фразе.
3. confidence + reason; закрытия, слияния, переназначения и низкая уверенность — на подтверждение человеку.

## Рекомендация: граф как модель в Postgres (вариант A)
Узлы: Project, Meeting, Participant, Task (shortCode T-n, текущий статус), Decision (D-n), ProjectMemory (версия сводки на встречу).
Рёбра: TaskMention (цитата, таймкод, спикер, kind), TaskEvent (журнал изменений: validAt / recordedAt / supersededAt, source LLM|USER, confidence, reviewState AUTO|PENDING|CONFIRMED|REJECTED), TaskLink (DEPENDS_ON | DUPLICATE_OF | SUPERSEDES | SUBTASK_OF), DecisionMention, Decision→Task.
Статусы: open → in_progress → done | cancelled | postponed; переходы проверяет код.
Пайплайн (задача BullMQ после протокола): Extract по транскрипту → проверка цитат → кандидаты (все открытые задачи проекта; позже pgvector + pg_trgm) → Resolve (structured output NEW|UPDATE|CLOSE|DUPLICATE|NO_CHANGE) → Gate (авто/на подтверждение) → новая версия сводки.
Обратно в промпт следующей встречи: `<project_memory>` — сводка 500–1500 токенов + открытые задачи с кодами + последние решения (+2–5 тыс. токенов).
Обходы глубины 2–3 — WITH RECURSIVE; при росте таблицы выгружаются в Neo4j/AGE без потерь.

Не подтверждено: механизм Read AI; трекинг у Otter/Fireflies/tl;dv; число вызовов Graphiti; паритет Mem0 TS.
