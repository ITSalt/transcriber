# Модернизация Transcrib до продукта — итог программы

Программа `product`, закрыта 2026-10-10. Одна программа — одна цель: новая цель — новая программа.

## Цель и условие завершения

Превратить Transcrib из открытого однопользовательского MVP в продукт для нескольких
пользователей: вход по PIN, изолированные рабочие пространства, список задач, проекты с
накопленным контекстом, который реально улучшает распознавание и протокол, и сбор обратной
связи по протоколам для следующей программы (улучшение воркфлоу протоколов).

Условие завершения: пункты 1–5 ниже подтверждены фактами на PROD https://transcriber.itsalt.ru (SELECT, curl, живые сценарии владельца, отчёты verify).

1. Без входа любой `/api/*`, кроме `/api/health` и `/api/auth/login`, отвечает 401; SPA
   показывает экран входа.
2. Два пользователя в разных пространствах: GET/PUT/DELETE/скачивание/PDF/SSE чужой встречи по
   известному id отвечают 404; список задач пользователя содержит только встречи его пространств
   (живой сценарий + интеграционный тест изоляции по всем маршрутам).
3. Встреча, запущенная с проектом и контекстом: в запросе к Deepgram есть `keyterm` из
   участников/глоссария, в промпте LLM — типизированные секции контекста; снимок контекста и
   метаданные генерации сохранены (SELECT).
4. Пользователь отправил обратную связь всех трёх видов (текст, исправленный протокол, файл .docx);
   записи и файлы видны SELECT'ом и в S3; исходный сгенерированный протокол не перезаписан.
5. Пакеты программы в DONE. Затем `close`; анализ обратной связи — следующая программа.
6. Терминология (D-40..D-44, добавлено 2026-10-09): на PROD меню «Встречи» и «Проекты и
   поручения», список встреч показывает название и проект, вкладка проекта «Поручения», новый
   протокол содержит «## Поручения» и «Спикер N», поле «Количество спикеров» отсутствует и
   колонка удалена (SELECT), глоссарий графа в UTF-8 с русскими названиями и терминами
   программы (запрос к графу).

## Результат

Условие завершения выполнено на PROD https://transcriber.itsalt.ru: (1) без входа /api/* кроме health/login → 401, SPA показывает экран входа (R-16, verify WP-FRONTEND-02); (2) два пользователя в разных пространствах, чужая встреча → 404 на GET/PUT/DELETE/PDF/SSE/скачивании, списки изолированы (R-18, auth-isolation.db.test.ts); (3) встреча с проектом и контекстом: keyterm в запросе Deepgram, типизированные секции контекста в промпте LLM, снимок контекста и метаданные генерации сохранены (R-19, SELECT); (4) обратная связь трёх видов: 4 записи protocol_feedback (COMMENT×2, CORRECTED_PROTOCOL, DOCX_REVIEW с файлом в S3 и разбором комментариев), исходная версия протокола не изменена (R-20); (5) все пакеты DONE — 31 пакет, последний WP-FRONTEND-09 (PR #42, 2ce6ebe391); (6) терминология D-40..D-44 на проде: меню «Встречи»/«Проекты и поручения», «Спикер N», секция «## Поручения», поле числа спикеров удалено вплоть до колонки БД, глоссарий графа 48 терминов approved в UTF-8. ## Решения

- D-1 (2026-10-07): Добавить .worktreeinclude (.env, .env.local) в корень transcriber. Исполняется пунктом первого пакета программы (оркестратор не правит код модуля; отдельный merge в main ради одного файла запустил бы деплой прода)
- D-2 (2026-10-07): Потоки подтверждены: backend = api/**, worker/**; frontend = web/**; общие пути под блокировкой — как в orch.yaml
- D-3 (2026-10-07): Staging не поднимаем: работаем с одним прод-стендом. Каждый merge в main = деплой прода, поэтому merge строго по одному (sequential), после каждого — verify --env prod; миграции данных — только обратимые/аддитивные, с бэкапом БД владельцем перед merge; пакеты, меняющие поведение для существующих пользователей, проектируются так, чтобы не ломать прод между merge
- D-4 (2026-10-07): Владелец передаёт доставку: сессии модулей коммитят и пушат свои feature-ветки и открывают PR; оркестратор мержит принятые PR в main только через orch.py deliver --apply (гейты G1-G10, по одному, squash) и проверяет выкладку. Так как merge в main = деплой прода (D-3), это включает выкладку в прод. Сессии модулей по-прежнему не мержат и не деплоят. Ограничение: миграции БД накатываются деплоем автоматически, поэтому пакет с миграцией получает пункт владельца «бэкап БД прода» с пометкой «блокирует доставку» и мержится только после его закрытия
- D-5 (2026-10-07): Дизайн: в transcriber/web своей дизайн-системы нет (стоковый shadcn, web/src/styles/globals.css) — переносим токены ITSALT Diorama из itsalt-site/web/assets/css/tokens.css и fonts.css на темы Tailwind v4; только светлая тема
- D-6 (2026-10-07): Пространство — единица изоляции: все участники видят всё в нём; у каждого пользователя личное пространство, общие — по членству
